一句话承诺

Sotto 看不到你的任何消息内容。你的消息、语音、文件在离开设备前已经完全加密，中继服务器只负责路由密文信封，无法解密也无法审查。

我们收集什么

Sotto 的设计目标是最小化数据收集。下表是 App 运行过程中经过网络传输的全部数据：

数据类型是否明文用途
消息密文（信封 body）否 — E2EE 密文中继仅做存储转发，无法读取
发送方 / 接收方公开标识符是（伪匿名）消息路由，不关联真实身份
消息 ID / 创建时间 / TTL是去重、排序、过期清理
订阅验证请求（purchaseToken）是Google Play 订阅权益校验

中继服务器可见的信封结构

中继收到的每一条消息是一个 JSON 信封，字段如下：

{
  "id":        "8f3a...c2d1",       // UUID，去重用
  "from":      "key_abc...xyz",    // 发送方公开标识符
  "to":        "key_def...uvw",    // 接收方公开标识符
  "body":      "AQID...base64",    // E2EE 密文 blob
  "ttl":       86400,              // 存活秒数
  "createdAt": "2026-11-17T08:00:00Z"
}

关键点：body 字段是 AEAD 加密后的完全密文，只有持有对应私钥的接收方才能解密。中继、开发者、第三方均无法读取。

消息的生命周期

1. 发送前（设备本地）

  • 明文消息使用 double ratchet 协议（Signal Protocol 变体）加密
  • 密钥存储在 Android Keystore / iOS Keychain，App 进程外无法读取
  • 加密后的密文 blob 写入本地 SQLite 数据库 — 数据库文件本身可能被直接读取，但消息体已是完全密文，无法还原

2. 中继传输（relay.sottorelay.com）

  • 中继收到的是密文信封，不解密、不审查、不记录内容
  • 信封有 TTL（默认 24 小时），过期后自动删除
  • 接收方拉取并 ack 后，中继立即清除该副本
  • 频道广播使用可配置的历史保留窗口（默认 7 天）

3. 接收后（设备本地）

  • 私钥解密，明文仅存于本地加密数据库
  • 不回传"已读"等任何状态到中继
  • 用户可随时删除消息，删除操作只影响本地

"看完即焚"模式：发件方可设置消息 TTL 为负数（表示"保留到被取走"），接收方拉取后立即销毁；或设置极短 TTL（如 30 秒），中继到期自动清除。

第三方服务

Cloudflare（中继基础设施）

relay.sottorelay.com 运行在 Cloudflare Workers + R2 对象存储上。Cloudflare 作为基础设施工具，处理信封的存储和转发。Cloudflare 的 隐私政策 适用。Sotto 中继层不配置任何 IP 日志，不使用 Cloudflare Analytics。

Google Play Billing（订阅支付）

Pro 订阅通过 Google Play 结算。支付流程由 Google 完成，Sotto 仅收到一个 purchaseToken，发送到独立的权益校验服务验证。校验请求不包含用户身份信息，只有 packageName、productId、purchaseToken 和 entitlementId 四个字段。Google 的 隐私政策 适用。

WebRTC（音视频通话）

实时音视频通话使用 WebRTC 媒体层，信令（会话建立、密钥协商）通过 E2EE 加密的 double ratchet 通道交换。通话期间会产生 ICE 候选的网络请求（用于 P2P 打洞），STUN/TURN 服务器只处理 NAT 穿透数据包，不存储通话内容。

用户权利

根据 GDPR、加州 CCPA、中国 PIPL 等适用法律，你拥有以下权利：

  • 访问权：请求获取中继上与你相关的全部数据（密文信封列表）
  • 删除权：请求从中继上清除你的所有信封
  • 反对权：反对基于合法利益的数据处理（但 Sotto 实际上不做这类处理）

由于 Sotto 不持有任何用户身份信息，行使这些权利可能需要你提供中继可见的公开标识符（public key hash）。请通过下方联系方式提出请求。

儿童隐私

Sotto 不面向 13 岁以下儿童。App 不收集、存储或处理儿童的个人信息。如果我们发现 13 岁以下的用户使用了 Sotto，将按法律要求删除相关数据。

安全措施

  • 传输中加密：所有 HTTP 请求使用 TLS 1.3；relay 证书固定（certificate pinning）
  • 静态加密：密钥由 Android Keystore / iOS Keychain 硬件保护；消息体在写入本地数据库前已完成 E2EE 加密
  • 前向保密：double ratchet 协议保证即使某个会话密钥泄露，历史消息仍安全
  • 签名校验：订阅权益回执使用 Ed25519 签名校验，不依赖传输层安全
